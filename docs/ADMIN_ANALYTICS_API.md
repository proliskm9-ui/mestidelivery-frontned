# Analytics, dispatch, KPI, reviews, audit — what the admin expects from the server

Pages: **Диспетчерская** (`AdminDispatch.tsx`), **Аналитика** (`AdminAnalytics.tsx`, tabs Продажи /
Рестораны / Курьеры), **Отзывы** (`AdminReviews.tsx`), **Журнал действий** (`AdminAudit.tsx`).
Paths are in `ANALYTICS_API` in `src/pages/Admin/analytics.ts`. Everything is computed in the browser
from `GET /api/orders?limit=10000`, so most of the work is **adding fields to that response**.
Until a field/endpoint exists the page shows "—" or a short notice; nothing breaks.

## 1. Extra fields on each order (`GET /api/orders`)

| Field | Used for | Set when |
|---|---|---|
| `accepted_at` | restaurant "Принимает" (created → accepted) | status → `confirmed` |
| `ready_at` | restaurant "Готовит" (accepted → ready) | status → `ready` |
| `picked_up_at` | courier delivery time | status → `delivering` |
| `delivered_at` | courier time, average delivery time | status → `delivered` |
| `courier_id`, `courier_name` | courier stats, dispatch cards | courier takes the order |
| `tips` | courier tips | order creation (already stored) |
| `rating`, `rating_comment` | Отзывы, restaurant/courier rating | `POST /api/orders/:id/rate` (already exists) |
| `user_id` | new vs repeat customers, "Компенсировать" | already sent |
| `delivery_lat`, `delivery_lng` | dispatch map pins | already sent |

Simplest implementation: an `order_status_log(order_id, status, created_at)` table written on every
status change, and the four `*_at` fields selected as `MIN(created_at)` per status.

## 2. Restaurants

`commission_percent NUMERIC(5,2) NULL` on restaurants, returned by `GET /restaurants/` and accepted by
the existing `PUT /restaurants/:id`. The Рестораны tab edits it inline and shows commission in GEL
(revenue × %). Restaurants also need `latitude`/`longitude` for the dispatch map (already in the type).

## 3. Dispatch

- `GET /api/admin/couriers/live` → `[{ id, name, lat, lng, updated_at, is_online, active_orders }]`
  from the last `POST /courier/location` of each courier (drop points older than ~5 min).
- `POST /api/admin/rush` `{ is_rush: boolean }` → `{ ok: true }`. Must flip what
  `GET /api/bot/v1/rush-status` returns (the site already shows the rush badge and longer ETA from it).

## 4. KPI plans and awards

Until these exist the admin keeps plans/awards in the browser's localStorage and says so.

```sql
CREATE TABLE kpi_plans (
  id          TEXT PRIMARY KEY,          -- generated by the admin
  target_type TEXT NOT NULL,             -- 'courier' | 'restaurant'
  target_id   TEXT NULL,                 -- NULL = everyone of that type
  title       TEXT NOT NULL,
  metric      TEXT NOT NULL,             -- 'deliveries' | 'orders' | 'revenue'
  period      TEXT NOT NULL,             -- 'week' | 'month' (calendar)
  target      NUMERIC NOT NULL,
  reward_gel  NUMERIC NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE awards (
  id          TEXT PRIMARY KEY,
  target_type TEXT NOT NULL,
  target_id   TEXT NOT NULL,
  target_name TEXT,
  amount      NUMERIC NOT NULL,          -- GEL, paid outside the site
  reason      TEXT NOT NULL,
  plan_id     TEXT NULL,
  admin       TEXT,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/admin/kpi-plans` | — | `KpiPlan[]` |
| POST | `/api/admin/kpi-plans` | `KpiPlan` | saved plan |
| DELETE | `/api/admin/kpi-plans/:id` | — | `{ ok: true }` |
| GET | `/api/admin/awards` | — | `Award[]`, newest first |
| POST | `/api/admin/awards` | `Award` | saved award |

Nice to have: show a courier their own plan progress and awards in the courier app (`/courier/stats`).

## 5. Audit log

`GET /api/admin/audit-log` → `[{ id, admin, action, target, details, created_at }]`, newest first.
Write a row from every admin mutation: `bonus_adjust`, `customer_block` / `customer_unblock`,
`referral_cancel`, `order_status`, `order_refund`, `promo_create` / `promo_update`,
`commission_change`, `award`, `product_update`, `restaurant_update`, `login`.
`target` is human-readable ("Клиент #101", "Заказ #1042", "BBQ Garden").

## Scores (for reference — computed in the admin)

- Restaurant 0–100: rating 35% (4.9 → 100, 3.5 → 0), cancellations 25% (0% → 100, 15% → 0),
  accept time 20% (2 min → 100, 12 min → 0), cook time 20% (12 min → 100, 40 min → 0).
- Courier 0–100: deliveries 40% (relative to the best courier), delivery time 30% (15 → 100, 45 → 0),
  rating 30%. Missing metrics are skipped and the weights re-normalised.

## Map tiles

Carto basemaps now answer "API KEY REQUIRED". The courier map and the dispatch map use
`tile.openstreetmap.org` (`src/lib/delivery/mapTiles.ts`). For heavy traffic get a free MapTiler /
Stadia key and swap the URL there.
